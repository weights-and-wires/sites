## The problem

The AlphaGo page ends with a program that still starts from human data and still carries Go-specific machinery. The pipeline has four trained models: a fast rollout policy, a supervised policy trained on 29.4 million human positions, a reinforcement-learning policy, and a value network. Leaves are scored by a mix of the value network and rollouts. A human expert's games bound where the system starts, and the whole recipe was designed around Go. The paper lists three Go properties that it says helped the networks: the rules are translation invariant, they are rotation and reflection symmetric, and the outcome is win or loss.

Chess and shogi don't have those properties. The introduction notes that their rules depend on position (pawns move two steps only from the second rank), are asymmetric (castling differs by side), and include long-range moves. Draws are common, and the paper says that the optimal solution to chess is believed to be a draw. The strongest programs, Stockfish in chess and Elmo in shogi, are alpha-beta search engines with hand-written evaluation functions, opening books, and endgame tables. Their authors tuned them over decades for one game each.

The question the paper asks is whether the AlphaGo Zero recipe works as a single general algorithm. The only inputs are the rules of the game and random initial weights. The answer in the abstract is that the same algorithm reached superhuman play in chess, shogi, and Go and defeated a world-champion program in each. In 100-game matches at one minute per move, AlphaZero won 28, drew 72, and lost 0 against Stockfish, won 90, drew 2, and lost 8 against Elmo, and won 60 of 100 against a three-day AlphaGo Zero (Table 1; the totals are computed by `scripts/paper_numbers.py`).

This page cites the arXiv version (v1, December 2017), which has no numbered sections. The Science version (2018) is not the source of any number here. The one numbered equation is Equation 1, so other citations name figures, tables, or Methods headings.

## Key ideas

The notation follows the paper: a position $s$, a network $f_\theta$ with weights $\theta$ that returns $(p, v)$, a policy $\pi$ from search, and a game outcome $z \in \{-1, 0, +1\}$. The exercises use `logits`, `pi`, and `z` for the same quantities. Every number in a worked example comes from a script in `scripts/`. Run any script from the paper folder to reproduce its output. The scripts need Python 3 and NumPy only. Numbers quoted from the paper, such as Elo curves and match results, don't come from a script, except for arithmetic on its tables.

The AlphaGo page explains PUCT selection, leaf evaluation, and backup. This page doesn't repeat them. It covers what AlphaZero changes. The table summarizes the changes against AlphaGo (Nature, 2016); the sections after it take them one at a time.

| | AlphaGo | AlphaZero |
|---|---|---|
| Trained models | $p_\pi$, $p_\sigma$, $p_\rho$, $v_\theta$ | One network $(p, v) = f_\theta(s)$ |
| Human data | 29.4 million KGS positions for $p_\sigma$ | None, only the rules |
| Policy training signal | Imitation, then $z_t \nabla \log p_\rho$ | Cross-entropy to the search policy $\pi$ |
| Priors in the search | From $p_\sigma$ | From $f_\theta$ itself |
| Leaf evaluation | $(1 - \lambda)\, v_\theta + \lambda\, z_L$ from a rollout | The network's $v$, with no rollouts |
| Outcome | Win or loss | Win, draw, or loss in $[-1, 1]$ |
| Who generates data | Fixed stages | The latest $f_\theta$, updated continually |
| Symmetry augmentation | Eight board symmetries in Go | None for chess and shogi |

### One network with two heads and one loss

**Intuition.** Four models become one. The network reads the position and returns a probability for each move (the policy head) and a number that says how the player to move is doing (the value head). The search uses the policy as a prior and the value in place of a rollout. Both heads share the same body, so features that help predict the outcome also help predict good moves.

**Math.** The network is $(p, v) = f_\theta(s)$, with $p_a = \Pr(a \mid s)$ and $v \approx \mathbb{E}[z \mid s]$ (introduction). After a game ends, every position $s_t$ from it is paired with the search policy $\pi_t$ and the outcome $z$. The parameters follow gradient descent on the sum of a mean-squared error, a cross-entropy, and an L2 penalty (Equation 1):

$$
(p, v) = f_\theta(s), \qquad l = (z - v)^2 - \pi^\top \log p + c\,\lVert\theta\rVert^2
$$

Here $c$ sets the L2 weight. The value $v$ estimates the *expected outcome*, so draws with $z = 0$ fit. AlphaGo Zero optimized the probability of winning under binary outcomes, and the paper lists this as one difference. The paper doesn't give the value of $c$ in this text, because it says that unless otherwise specified the training and search parameters are identical to AlphaGo Zero.

**Tiny example, computed by `scripts/loss_example.py`.** Take four moves with logits $[1.0, 0.5, 0.0, -1.0]$, so $p = [0.4740, 0.2875, 0.1744, 0.0641]$. The search target is $\pi = [0.6, 0.3, 0.1, 0]$, the value is $v = 0.3$, the game was lost ($z = -1$), and the L2 term is $c\lVert\theta\rVert^2 = 10^{-4} \cdot 50 = 0.0050$. The terms are:

| Term | Value |
|---|---|
| $(z - v)^2 = (-1.3)^2$ | 1.6900 |
| $-\pi^\top \log p$ | 0.9966 |
| $c\lVert\theta\rVert^2$ | 0.0050 |
| $l$ | 2.6916 |

The policy term has a floor. When $p = \pi$ it equals the entropy of $\pi$, 0.8979, and not 0. The gradient of $l$ with respect to the logits is $p - \pi = [-0.1260, -0.0125, 0.0744, 0.0641]$. It pushes the logit of move 0 up and the logits of moves 2 and 3 down. The gradient with respect to $v$ is $-2(z - v) = 2.6$. The script checks both against finite differences.

Exercise 1 asks you to write this loss and its gradients.

### Visit counts are the policy target

**Intuition.** The network proposes moves, and the search tests the proposal. A move that the network ranks low but that wins in the simulations collects visits anyway, and a move that looks good but loses stops getting visits. The root visit counts are therefore a better policy than the network's own output. Training the policy head to match them pulls the network toward what search found.

**Math.** After the simulations, the search returns a vector $\pi$ over moves that is either proportional to the root visit counts or greedy with respect to them (introduction). In the AlphaGo Zero convention that AlphaZero inherits, this is a temperature $\tau$:

$$
\pi(a \mid s_{\text{root}}) = \frac{N(s_{\text{root}}, a)^{1/\tau}}{\sum_b N(s_{\text{root}}, b)^{1/\tau}}
$$

At $\tau = 1$ this is the visit share. As $\tau \to 0$ it puts all the mass on the most visited move. The paper's Methods ("Configuration") say that training moves are selected in proportion to the root visit count, and that evaluation moves are selected greedily. The text of this paper does not give a temperature schedule, so any schedule, such as the one in AlphaGo Zero, is not a claim about this paper. The paper also doesn't give $c_{\text{puct}}$ or the network's size.

**Tiny example, computed by `scripts/visit_targets.py`.** Root visit counts $N = [60, 30, 8, 2]$ (100 simulations) give these targets:

| $\tau$ | $\pi$ |
|---|---|
| 2 | [0.4435, 0.3136, 0.1619, 0.0810] |
| 1 | [0.6000, 0.3000, 0.0800, 0.0200] |
| 0.5 | [0.7881, 0.1970, 0.0140, 0.0009] |
| 0.1 | [0.9990, 0.0010, 0.0000, 0.0000] |
| 0 | [1, 0, 0, 0] |

You can check the $\tau = 0.5$ row by hand: $N^2 = [3600, 900, 64, 4]$, which sums to 4568, and $3600 / 4568 = 0.7881$. A direct power fails at small $\tau$. At $\tau = 0.001$ the script prints `[nan nan nan 0.]` for the naive computation, because $60^{1000}$ overflows, and `[1. 0. 0. 0.]` for the computation in log space.

Exercise 2 asks you to write the conversion.

### Self-play with one network that updates continually

**Intuition.** Both sides of every game use the same network, which starts out random. Early games are close to random, but they still end in a win, a loss, or a draw, and the outcome is a label. The search makes each move a little better than the network alone. Training on those moves and outcomes makes the next network slightly stronger, which makes the next games stronger.

**Math.** Games are played by MCTS for both players, with moves drawn $a_t \sim \pi_t$ (introduction). At the end the terminal position $s_T$ is scored by the rules as $z = -1$, $0$, or $+1$, from the view of the player to move at $s_t$, so the label alternates sign along the game. AlphaGo Zero kept a "best player" and promoted a new network only if it won 55% of an evaluation match. AlphaZero drops the match. It keeps one network that is updated continually, and self-play uses the latest parameters (introduction). The scale is in Table S3: 700,000 steps with minibatches of 4,096 positions, 5,000 first-generation TPUs to generate games, and 64 second-generation TPUs for training. Chess took 9 hours and 44 million games, shogi 12 hours and 24 million, and Go 34 hours and 21 million. Training used 800 simulations per move.

**Tiny example, computed by `scripts/selfplay_nim.py`.** The game is Nim from the AlphaGo page: a pile of $n$ stones, take 1, 2, or 3, and the player who takes the last stone wins. One self-play game from 7 stones, with 100 simulations, a uniform prior, and an exact value function, produces three tuples $(n, \pi, z)$:

| $n$ | $\pi$ | $z$ |
|---|---|---|
| 7 | [0.04, 0.03, 0.93] | +1 |
| 4 | [0.49, 0.29, 0.22] | -1 |
| 3 | [0.04, 0.03, 0.93] | +1 |

The player at 7 takes 3 and leaves 4. The player at 4 loses whatever they play, which is why the search is undecided there ($\pi$ is nearly flat). The player at 3 takes all three. The last mover wins, so $z$ is $+1$ there and alternates back up the list.

The script then closes the loop with a tabular "network", one row of logits and one value per pile size, initialized with small random numbers. It plays 12 games per iteration from 15 stones with 40 simulations and root noise, then takes five gradient steps on the loss. No strategy is supplied, only the rules:

| Iteration | Policy head alone picks the winning move | Value head has the right sign |
|---|---|---|
| 0 | 4 of 12 winning piles | 0 of 15 piles |
| 1 | 9 of 12 | 13 of 15 |
| 2 | 11 of 12 | 13 of 15 |
| 5 | 12 of 12 | 14 of 15 |
| 10 | 12 of 12 | 15 of 15 |
| 30 | 12 of 12 | 15 of 15 |

By iteration 10 the value head has the right sign for every pile, and by iteration 5 the policy head picks the winning move in all 12 winning piles (the 3 piles that are multiples of 4 have no winning move, so they don't count). The policy head alone, with no search, is then a perfect Nim player on this range. This toy is not a result from the paper. The search in Nim reaches the end of the game in a few dozen simulations, so the labels are easy to get.

### Noise at the root keeps self-play exploring

**Intuition.** If the network assigns a move a prior near zero, PUCT hardly ever visits it, so $\pi$ gives it almost no mass, so the next network assigns it an even smaller prior. A mistake in the network can freeze itself in. Noise at the root gives every legal move a small chance of a visit in every game.

**Math.** Dirichlet noise $\text{Dir}(\alpha)$ is added to the prior at the root node. The prior becomes $P(s_{\text{root}}, a) = (1 - \varepsilon)\, p_a + \varepsilon\, \eta_a$ with $\eta \sim \text{Dir}(\alpha)$. The paper scales the noise in inverse proportion to the typical number of legal moves, with $\alpha = 0.3$ for chess, $0.15$ for shogi, and $0.03$ for Go (Methods, "Configuration"). It is the one hyperparameter that the paper changes per game. The mixing weight $\varepsilon = 0.25$ is the AlphaGo Zero value. It does not appear in this text, and this page has not checked it against the Science version. A Dirichlet with a small $\alpha$ is spiky: it puts most of its mass on one or two moves. A Dirichlet with a large $\alpha$ is nearly uniform. With $K$ legal moves, $\alpha K$ is the total concentration.

**Tiny example, computed by `scripts/root_noise.py`.** The noise is a mixture, so the mean of the mixed prior is $(1 - \varepsilon)\, p + \varepsilon / K$ for equal $\alpha$. For $p = [0.90, 0.06, 0.03, 0.01]$ and $\alpha = 0.3$, 20,000 draws average $[0.7386, 0.1069, 0.0847, 0.0698]$, against the formula's $[0.7375, 0.1075, 0.0850, 0.0700]$. A move with $p = 0.01$ keeps at least $(1 - \varepsilon) \cdot 0.01 = 0.0075$, and the noise can lift it far higher. For rough legal-move counts of 35 (chess), 80 (shogi), and 250 (Go), the product $\alpha K$ is 10.5, 12.0, and 7.5. It stays in one range while $\alpha$ changes tenfold. The first and last counts come from the AlphaGo page. The shogi count of 80 is an approximation that the paper does not give. The mean share of the largest noise component is then 0.219, 0.185, and 0.238.

Exercise 3 asks you to write the noise function with a legal-move mask.

### Same algorithm, three games

**Intuition.** Only the encoding of the board and of the moves is game-specific, and both are mechanical consequences of the rules. The rest is the same code.

**Math.** The board is an $N \times N \times (MT + L)$ stack with $T = 8$ steps of history, from the view of the current player (Methods, "Representation", Table S1). The totals are 17 planes for Go, 119 for chess, and 362 for shogi. Chess has 14 planes per time step (6 piece types for each side, plus repetition planes) and 7 constant planes (colour, move count, castling, and no-progress count), so $14 \cdot 8 + 7 = 119$. The policy for chess is an $8 \times 8 \times 73$ stack of planes, which gives 4,672 moves. A position is "pick up the piece here", and the plane says how it moves (56 queen-like moves, 8 knight moves, and 9 underpromotions). Shogi has $9 \times 9 \times 139 = 11{,}259$ moves, and Go has $19 \times 19 + 1 = 362$ (stones plus pass). Illegal moves are masked to probability 0 and the rest are renormalized, which is the mask in exercise 3.

The paper lists four more differences. Chess and shogi games past a maximum length count as draws, while Go is scored with Tromp-Taylor rules. AlphaZero does not augment the data with symmetries and does not transform positions during search for chess and shogi, because the rules are asymmetric. It reuses one set of hyperparameters with no Bayesian optimization, apart from the noise. And it trains a separate network for each game.

**Tiny example, computed by `scripts/paper_numbers.py`.** The arithmetic above (17, 119, 362 planes and 4,672, 11,259, 362 moves) is printed by the script.

### Results, and why search can be 875 times slower

**Intuition.** Alpha-beta engines look at tens of millions of positions per second and use hand-written scores. AlphaZero looks at tens of thousands and uses a network to pick which branches to look at.

**Math.** Elo ratings come from one-second-per-move tournaments between training checkpoints and a baseline anchored to published values, estimated by BayesElo with $c_{\text{elo}} = 1/400$ (Methods, "Evaluation"). The paper reports that AlphaZero passed Stockfish in chess after 4 hours (300,000 steps), Elmo in shogi after under 2 hours (110,000 steps), and AlphaGo Lee in Go after 8 hours (165,000 steps) (Figure 1). Table S4 gives the search speed: 80,000 positions per second in chess, 40,000 in shogi, and 16,000 in Go, against 70 million for Stockfish and 35 million for Elmo. The paper says AlphaZero compensates by using the network to focus on the most promising lines. It also argues that MCTS averages the network's approximation errors over a subtree, so they tend to cancel, whereas alpha-beta propagates the largest error to the root (Methods, "MCTS and Alpha-Beta Search"). Figure 2 shows that AlphaZero's search scaled better with thinking time than either engine, and the paper notes that draws compress the chess Elo scale.

**Tiny example, computed by `scripts/paper_numbers.py`.** Table 1's chess matches add to 28 wins, 72 draws, and 0 losses. A draw is half a point, so the score is $0.640$ and the Elo gap is about $400 \log_{10}(0.64 / 0.36) = +100$. The same formula gives about $+402$ for shogi (90 wins, 2 draws, 8 losses) and $+70$ for Go against AlphaGo Zero. These gaps are this page's arithmetic on 100-game matches, and not figures from the paper. Stockfish searches $70{,}000{,}000 / 80{,}000 = 875$ times more positions per second. The chess run passed Stockfish at 43% of its 700,000 steps. Sampling 2.87 billion positions from 44 million chess games reads each game about 65 times, 119 times for shogi, and 137 times for Go.

## Pitfalls

- **Training the policy head on the network's own output.** The target is the search policy $\pi$ from visit counts, and not $p$. If you train on $p$, nothing improves it.
- **Training the policy head on the move that was played.** With $\tau = 1$ early in the game, the move that was played is a sample from $\pi$. The loss uses the whole vector $\pi$, and `scripts/selfplay_nim.py` stores the $\tau = 1$ share even on greedy moves. A one-hot target discards the information about the other moves.
- **Expecting the policy loss to reach zero.** The floor of $-\pi^\top \log p$ is the entropy of $\pi$, which is 0.8979 in the example. A flat curve above zero is normal.
- **Computing $N^{1/\tau}$ directly.** It overflows for small $\tau$ and for large counts. Take logits $\log N / \tau$, subtract the maximum, and exponentiate. Handle $\tau = 0$ as its own case, with ties shared.
- **Giving each player's view the same sign of $z$.** The outcome is from the view of the player to move at $s_t$, so it alternates along the game. If every position gets the winner's $z$, the value head learns who wins in general and not who is ahead.
- **Applying noise below the root.** The Dirichlet noise goes in at the root only. At other nodes the prior is the plain network output.
- **Putting noise on illegal moves.** Draw $\eta$ over the legal moves only, and give illegal moves 0. Otherwise the mixed prior leaks probability onto moves that can't be played.
- **Copying $\alpha = 0.03$ to a small game.** The value is tied to the number of legal moves. With 3 legal moves, $\alpha = 0.03$ gives noise that puts nearly everything on one move. The Nim script uses $\alpha = 0.5$ for $K = 3$.
- **Assuming a champion gate.** AlphaGo Zero gated each new network behind a 55% evaluation match. AlphaZero doesn't. Implementations that keep a gate are AlphaGo Zero's, and not this paper's.
- **Assuming a Go-only trick carries over.** The eight-fold symmetry augmentation is for Go. The paper does not use it for chess and shogi.
- **Citing numbers the text does not give.** This text does not give $c$, $c_{\text{puct}}$, the temperature schedule, the network depth, or $\varepsilon$. They come from AlphaGo Zero. This page marks which numbers it reads from the paper.
- **Treating the toy as the paper.** The Nim loop uses a lookup table, 40 simulations, and one start position. The paper uses a deep network, 800 simulations, and thousands of TPUs.
