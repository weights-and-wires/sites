## The problem

Before this paper, the successful RL systems that read images relied on hand-built features and a linear value function (Section 1). The quality of the features set a ceiling on performance. The natural fix is to feed raw pixels to a deep network, but Section 1 lists three reasons why a deep network and Q-learning don't combine easily:

- **Sparse, delayed reward.** Supervised learning gets a label for every input. An RL agent gets a scalar reward that can arrive thousands of time steps after the action that earned it.
- **Correlated samples.** Deep learning assumes independent samples. Consecutive frames of a game are nearly the same, so a minibatch of consecutive frames is nearly one sample.
- **A moving data distribution.** The data come from the agent's own policy, so the data change whenever the network changes.

Section 3 adds that Q-learning with a nonlinear function approximator, or with off-policy data, was known to diverge. The field had mostly retreated to linear approximators, which have better convergence guarantees.

Here is a failing example that you can run. Take a 5x5 gridworld where the agent starts in the top-left corner and gets reward $+1$ for reaching the bottom-right corner. A small network reads the agent's coordinates and outputs four Q-values. Train it with the plain online Q-learning update of Section 2: one gradient step per environment step, on the transition that just happened. Over 20 seeds at learning rate 0.05, only 2 of 20 networks end up with a greedy policy that reaches the goal. The same network with the replay memory of this paper reaches the goal in 16 of 20 (computed by `scripts/ablation.py`, with the full table in the replay section below).

The paper's answer, on seven Atari 2600 games, is the algorithm in Section 4. Table 1 reports 168 average points on Breakout for the network, against 6 for the best earlier learning method in the table (Contingency) and 31 for the human expert. On Pong it reports 20, against a human score of -3. The same architecture and hyperparameters run on all seven games (Section 5), except that Space Invaders uses frame skip $k = 3$ and the others $k = 4$.

## Key ideas

The sections that follow use the paper's notation: the emulator $\mathcal{E}$, the sequence $s_t$, the preprocessed sequence $\phi_t = \phi(s_t)$, the discount $\gamma$, the action-value function $Q(s, a; \theta)$ with weights $\theta$, and the replay memory $\mathcal{D}$. Two small differences are mine. I write $d_j \in \{0, 1\}$ for a terminal flag, where the paper uses a case split on the next state. In the code and the exercises, $D$ also stands for the array of those flags. Every number comes from a script in `scripts/`; run any script from the paper folder to reproduce its output. The scripts `gridworld.py` and `ablation.py` need Python 3 with NumPy only.

### A Q-network trained on TD targets

**Intuition.** If you knew the optimal value $Q^*(s', a')$ of the next state for every action, the best action now would be the one that maximizes the reward plus the discounted best next value. The network is trained so that its output at $(s, a)$ moves toward that quantity. The target is built from the network's own prediction one step later, so the network chases a target that it also moves.

**Math.** The paper defines the optimal action-value function $Q^*(s, a)$ as the maximum expected return over all policies, and states the Bellman equation (Section 2, Equation 1):

$$
Q^*(s, a) = \mathbb{E}_{s' \sim \mathcal{E}}\left[\, r + \gamma \max_{a'} Q^*(s', a') \;\middle|\; s, a \right]
$$

A network $Q(s, a; \theta) \approx Q^*(s, a)$ is trained by minimizing a sequence of losses (Section 2, Equation 2):

$$
L_i(\theta_i) = \mathbb{E}_{s, a \sim \rho(\cdot)}\left[ \big(y_i - Q(s, a; \theta_i)\big)^2 \right], \qquad y_i = \mathbb{E}_{s' \sim \mathcal{E}}\left[\, r + \gamma \max_{a'} Q(s', a'; \theta_{i-1}) \;\middle|\; s, a \right]
$$

Here $\rho(s, a)$ is the behaviour distribution. The target $y_i$ uses the previous iteration's weights $\theta_{i-1}$, and those weights are held fixed while $\theta_i$ is optimized. Differentiating gives (Section 2, Equation 3):

$$
\nabla_{\theta_i} L_i(\theta_i) = \mathbb{E}_{s, a \sim \rho(\cdot);\, s' \sim \mathcal{E}}\left[ \left( r + \gamma \max_{a'} Q(s', a'; \theta_{i-1}) - Q(s, a; \theta_i) \right) \nabla_{\theta_i} Q(s, a; \theta_i) \right]
$$

Two details about this equation are easy to miss.

- **Equation 3 is not the exact gradient of Equation 2.** The gradient of the squared error carries a factor of $-2$. Equation 3 equals $-\tfrac{1}{2} \nabla_{\theta_i} L_i$. The sign and the 2 disappear into the direction of the update and the learning rate.
- **Algorithm 1 doesn't keep a separate copy $\theta_{i-1}$.** Its target line uses the current weights $\theta$, so the "previous iteration" is the previous step. Also, the algorithm writes $\max_a Q^*(\phi(s_t), a; \theta)$ for action selection, where $Q^*$ is a typo for the network $Q$.

With a minibatch of $B$ stored transitions $(\phi_j, a_j, r_j, \phi_{j+1})$, Algorithm 1 sets

$$
y_j = \begin{cases} r_j & \text{if } \phi_{j+1} \text{ is terminal} \\ r_j + \gamma \max_{a'} Q(\phi_{j+1}, a'; \theta) & \text{otherwise} \end{cases}
$$

and takes a gradient step on $(y_j - Q(\phi_j, a_j; \theta))^2$. The target $y_j$ is a constant in the gradient.

**Tiny example, computed by `scripts/target_example.py`.** Take $\gamma = 0.9$, $K = 2$ actions, and three transitions:

| $j$ | $a_j$ | $r_j$ | $Q(\phi_j, \cdot)$ | $Q(\phi_{j+1}, \cdot)$ | terminal | $y_j$ | $y_j - Q(\phi_j, a_j)$ |
|---|---|---|---|---|---|---|---|
| 1 | 1 | 0 | `[0.5, 0.2]` | `[0.4, 0.8]` | no | $0 + 0.9 \cdot 0.8 = 0.72$ | 0.52 |
| 2 | 0 | 1 | `[0.5, 0.9]` | ignored | yes | 1 | 0.50 |
| 3 | 0 | -1 | `[0.1, 0.3]` | `[0.2, 0.1]` | no | $-1 + 0.9 \cdot 0.2 = -0.82$ | -0.92 |

The squared errors are 0.2704, 0.25, and 0.8464, so the mean loss is 0.4556. The gradient of that mean loss with respect to the three taken outputs $Q(\phi_j, a_j)$ is $[-0.3467, -0.3333, 0.6133]$, which is $-2(y_j - Q)/3$. Only the taken action's output gets a gradient. The other outputs of the same row get none. The script also checks that a terminal row gives $y = r$ whatever the next-state value is: setting it to $10^6$ leaves $y_2 = 1$.

### Experience replay breaks correlation

**Intuition.** Playing and learning from the same stream is like studying by reading only the last page you read. Instead, the agent writes every transition into a memory and trains on random picks from that memory. A minibatch then mixes transitions from many different moments and policies.

**Math.** After every step the agent stores $e_t = (\phi_t, a_t, r_t, \phi_{t+1})$ in a data set $\mathcal{D} = e_1, \dots, e_N$ pooled over many episodes. The inner loop applies Q-learning minibatch updates to samples $e \sim \mathcal{D}$ (Section 4). The memory keeps only the last $N$ tuples and samples uniformly, which the paper calls a limitation, because it neither favors important transitions nor keeps old ones. Section 4 gives three advantages:

1. **Data efficiency.** Each transition feeds many weight updates.
1. **Lower variance.** Consecutive samples are strongly correlated, and random samples are not.
1. **No feedback loop.** On-policy training lets the current weights decide the next data. If the best action is "move left", the data become all left-side states, and if the best action then flips, the data flip too. Replay averages the behaviour distribution over many past policies.

Because the memory holds transitions from old weights, learning must be off-policy, which is why the paper uses Q-learning (Section 4).

**Tiny example, computed by `scripts/ablation.py`.** The script trains the same two-layer network on the gridworld from the problem section for 4,000 steps, with the same $\epsilon$ schedule and 20 seeds per cell. The replay arm samples a minibatch of 32 from a memory of 2,000 transitions at every step. The online arm updates on only the newest transition. Each cell counts the seeds whose greedy policy reaches the goal:

| Learning rate | Replay | Online |
|---|---|---|
| 0.05 | 16 / 20 | 2 / 20 |
| 0.02 | 11 / 20 | 4 / 20 |
| 0.01 | 10 / 20 | 7 / 20 |
| 0.005 | 9 / 20 | 10 / 20 |
| 0.002 | 10 / 20 | 9 / 20 |

The best learning rate for each arm gives 16 of 20 for replay and 10 of 20 for online, and the online arm needs a small step size to avoid blowing up. Read this table with two cautions. The arms differ in two ways at once: replay decorrelates the data and also uses 32 samples per step against 1, so the table doesn't isolate the decorrelation. At small learning rates the two arms are about equal. This is a 4,000-step toy problem, not Atari.

The script also measures the correlation directly. On 2,000 consecutive transitions from the trained agent with $\epsilon = 0.3$, the lag-1 correlation of the row coordinate is 0.51. For two transitions drawn uniformly from the same memory, it is 0.00.

### Frame stacking for partial observability

**Intuition.** A single screen is a photograph. It shows where the ball is and not where it is going. Stacking the last few frames gives the network a short video clip, which carries velocity.

**Math.** The agent observes only the current screen $x_t$, so the task is partly observed and many emulator states are perceptually aliased (Section 2). The paper therefore works with sequences $s_t = x_1, a_1, x_2, \dots, a_{t-1}, x_t$ and treats each distinct sequence as a state of a large but finite MDP (Section 2). A network can't take a sequence of arbitrary length, so the function $\phi$ turns the sequence into a fixed-size input. In the experiments, $\phi$ converts each of the last 4 frames to grayscale, downsamples it to $110 \times 84$, crops an $84 \times 84$ region, and stacks the 4 results (Section 4.1). The crop exists only because the GPU convolution code the authors used expected square inputs.

**Tiny example, computed by `scripts/frames_and_network.py`.** A ball moves one cell per frame along cells 0 to 4 and reverses at the ends. With one frame, a ball at cell 2 could go to cell 1 or cell 3 next. With two stacked frames, the pair "1 then 2" always leads to cell 3, and the pair "3 then 2" always leads to cell 1. Two frames are enough here. The paper uses four, which also carry acceleration and more history. Four frames do not make the task fully observed, and the paper doesn't claim that. Frame skipping (Section 5) makes the stack cover more game time: the agent chooses an action every $k$-th frame and repeats it on the frames in between.

### The convolutional network and the training recipe

**Intuition.** The network takes the state and returns one Q-value per action. One forward pass then scores every action, and the action choice is an argmax over the output.

**Math.** Earlier work fed the history and one action in, and got one Q-value out. That design needs a separate forward pass per action. The paper instead gives the network one output unit per action, so a single pass gives all $K$ values (Section 4.1). The architecture is as follows (Section 4.1):

| Layer | Operation | Output shape |
|---|---|---|
| Input | 4 stacked grayscale frames | $84 \times 84 \times 4$ |
| Conv 1 | 16 filters, $8 \times 8$, stride 4, ReLU | $20 \times 20 \times 16$ |
| Conv 2 | 32 filters, $4 \times 4$, stride 2, ReLU | $9 \times 9 \times 32$ |
| Fully connected | 256 ReLU units | 256 |
| Output | linear, one unit per action | $K$ (4 to 18) |

The paper doesn't print the output shapes of the convolutional layers. I derived them, assuming no padding, from $\lfloor (n - k)/s \rfloor + 1$.

The training recipe comes from Section 5. The optimizer is RMSProp with minibatches of 32. The behaviour policy is $\epsilon$-greedy, with $\epsilon$ annealed linearly from 1 to 0.1 over the first million frames and fixed at 0.1 after that. Training runs for 10 million frames with a replay memory of one million most recent frames. Positive rewards become $+1$ and negative rewards become $-1$ during training only. Evaluation uses $\epsilon = 0.05$.

**Tiny example, computed by `scripts/frames_and_network.py` and `scripts/schedule_example.py`.**

- Parameters. Conv 1 has $8 \cdot 8 \cdot 4 \cdot 16 + 16 = 4{,}112$. Conv 2 has $4 \cdot 4 \cdot 16 \cdot 32 + 32 = 8{,}224$. The flattened size is $9 \cdot 9 \cdot 32 = 2{,}592$, so the fully connected layer has $2{,}592 \cdot 256 + 256 = 663{,}808$, and it holds almost all the weights. With $K = 4$ outputs, the output layer adds 1,028, for a total of 677,172. With $K = 18$, the total is 680,770. These counts include biases, which the paper doesn't discuss.
- Input size. A raw frame has $210 \cdot 160 \cdot 3 = 100{,}800$ values. The network input has $84 \cdot 84 \cdot 4 = 28{,}224$.
- Schedule. $\epsilon$ is 1.000 at frame 0, 0.775 at 250,000, 0.550 at 500,000, and 0.100 from 1,000,000 on. With $k = 4$, the 10 million frames are 2.5 million agent decisions, and $\epsilon$ reaches 0.1 after 250,000 decisions.
- Clipping. Scores of $-30, 0, 1, 4, 200$ become $-1, 0, 1, 1, 1$. A score of 200 and a score of 4 look the same to the agent, which the paper notes as a cost (Section 5).

Exercise 3 asks you to write the $\epsilon$ schedule and the action selection.

### Reading the training curves

**Intuition.** Average reward per episode is noisy, because a small change in the weights changes which states the policy visits. The average predicted Q on a fixed set of states is smoother.

**Math.** Section 5.1 collects a fixed set of states with a random policy before training and tracks the average of $\max_a Q(s, a; \theta)$ over those states. Figure 2 shows that this average rises much more smoothly than the average reward on Breakout and Seaquest. The paper also reports that it saw no divergence in any experiment, and it says this happens "despite lacking any theoretical convergence guarantees." Figure 3 (Section 5.2) shows the predicted value of Seaquest rising when an enemy appears, peaking just before the torpedo hits, and falling after the enemy vanishes.

## Pitfalls

- **Looking for a target network.** This paper has none. Algorithm 1 computes the target from the same weights that it updates. The separate, periodically frozen target network belongs to the later Nature paper, "Human-level control through deep reinforcement learning" (2015). Equation 2's $\theta_{i-1}$ describes the target as the previous iteration, and Algorithm 1 doesn't implement it as a frozen copy.
- **Bootstrapping through terminal states.** A terminal transition must give $y = r$. If you keep the $\gamma \max_{a'} Q$ term, the network learns values that leak across the end of an episode. The test in Exercise 1 uses a next-state value of $10^6$ to expose this.
- **Taking the max over the wrong axis.** The $\max$ is over actions, the last axis of a `(B, K)` array. A max over the batch axis returns a plausible-looking vector of the wrong length, or, with broadcasting, silently the wrong numbers.
- **Training every action output.** The loss involves only $Q(\phi_j, a_j)$. If you build the error vector for all $K$ outputs, you push the untaken actions toward a target that was computed for a different action.
- **Sampling empty slots.** Before the replay memory fills, the unused rows are zeros. Sample from the filled portion, or the network trains on all-zero transitions.
- **Overwriting the wrong end.** The memory should overwrite the oldest transition. A pointer that stops at the end keeps the oldest data forever.
- **Treating Equation 3 as the exact gradient of Equation 2.** It differs by a factor of $-\tfrac{1}{2}$. If you compute gradients by hand and compare with an autodiff library, include the 2.
- **Choosing the greedy action among the random ones.** In $\epsilon$-greedy as the paper describes it, the random branch picks any of the $K$ actions, including the greedy one. The greedy action then has probability $1 - \epsilon + \epsilon/K$.
- **Judging progress by reward alone.** Section 5.1 shows that average episode reward is noisy. Track the average maximum Q on a held-out set of states as well.
- **Mixing up frames and steps.** The paper counts frames: 10 million frames, an annealing period of one million frames, and a replay memory of one million frames. With frame skip $k = 4$, the agent makes one decision per 4 frames, so those counts correspond to a quarter as many decisions. The paper doesn't spell out whether the memory holds one million frames or one million decision steps, so check the official code if you need the exact value.
- **Expecting the 2013 numbers from a modern recipe.** The workshop paper uses a small network, RMSProp, 10 million frames, and no target network. Later work changed all of these.
